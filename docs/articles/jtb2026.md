# Get started with jtb2026

> Find the rows of a table that mention what you are looking for.

`jtb2026` does one thing: you hand it a table and a word, and it hands
back the rows that mention it. The table can be an Excel workbook, a
CSV, or a data frame you already have; the answer can be returned to R,
written to a CSV, or both.

There are two ways to ask the question, and the difference between them
is the whole point of the package:

|  | [`jtb_search_keyword()`](https://yh202109.github.io/jtb2026/reference/jtb_search_keyword.md) | [`jtb_search_semantic()`](https://yh202109.github.io/jtb2026/reference/jtb_search_semantic.md) |
|----|----|----|
| Asks | *Does this row contain the word?* | *How close is this row to the idea?* |
| Returns | Every match, in the original row order | The best matches, ranked, with a score |
| Finds `"nauseous"` when you search `"stomach upset"` | No | Yes |
| Reproducible, offline, no model | Yes | Yes |

Each has a vignette of its own:
[`vignette("keyword-search")`](https://yh202109.github.io/jtb2026/articles/keyword-search.md),
[`vignette("semantic-search")`](https://yh202109.github.io/jtb2026/articles/semantic-search.md)
and
[`vignette("files-and-output")`](https://yh202109.github.io/jtb2026/articles/files-and-output.md).

## Sixty-second tour

### Find rows containing a word

``` r

hits <- jtb_search_keyword(site_reports, "headache",
                           columns = c("term", "comment"))
hits[, c("report_id", "term", "comment")]
```

|  | report_id | term | comment |
|:---|:---|:---|:---|
| 1 | R001 | Headache | Subject reported a dull headache starting two hours after the morning dose; resolved without treatment. |
| 5 | R005 | Headache | Persistent head pain over three days, described as pressure behind the eyes. |
| 14 | R014 | Headache | Mild headche noted in the diary, no medication taken. |
| 21 | R021 | Headache | Sharp pain across the forehead, subject took paracetamol with relief. |

Four rows, in the order they appear in the table. Note the row names —
`1`, `5`, `14`, `21` — they are the positions in the input, so you can
always trace a result back.

### Find rows that *mean* something

Nobody in this table wrote “stomach upset”. The keyword search says so:

``` r

nrow(jtb_search_keyword(site_reports, "stomach upset", columns = "comment"))
#> [1] 0
```

The semantic search finds all four nausea rows anyway, ranked:

``` r

ranked <- jtb_search_semantic(site_reports, "stomach upset",
                              columns = "comment", top_n = 4)
ranked[, c("report_id", "term", "comment", ".score")]
```

|  | report_id | term | comment | .score |
|:---|:---|:---|:---|---:|
| 9 | R009 | Nausea | Stomach felt unsettled after each dose and the subject vomited once on Day 9. | 0.533332 |
| 24 | R024 | Nausea | Reported feeling sick to the stomach for an hour after dosing. | 0.403267 |
| 17 | R017 | Nausea | Nauseous most mornings this cycle, improving by midday. | 0.129933 |
| 2 | R002 | Nausea | Subject felt queasy through the afternoon and skipped the evening meal. | 0.115708 |

`R009` mentions the stomach directly and scores highest. `R002` only
says “queasy” and scores lowest. The ordering is the useful part: it is
a ranking, not a yes/no.

### Write the answer to a CSV

Both functions take `output_csv`. The file gets exactly what the
function returns.

``` r

out <- file.path(tempdir(), "headache_rows.csv")

hits <- jtb_search_keyword(site_reports, "headache", output_csv = out)

nrow(hits)
#> [1] 4
readLines(out, n = 2)
#> [1] "\"report_id\",\"site\",\"subject\",\"visit\",\"term\",\"comment\",\"severity\",\"outcome\",\"report_date\""                                                                                          
#> [2] "\"R001\",\"Boston\",\"S-1001\",\"Week 2\",\"Headache\",\"Subject reported a dull headache starting two hours after the morning dose; resolved without treatment.\",\"Mild\",\"Recovered\",2026-01-06"
```

## Which columns get searched

Both functions take `columns`, and it accepts three shapes. All three of
these search the same two columns:

``` r

by_name <- jtb_search_keyword(site_reports, "Nausea",
                              columns = c("term", "comment"))
by_position <- jtb_search_keyword(site_reports, "Nausea", columns = c(5, 6))

mask <- names(site_reports) %in% c("term", "comment")
by_mask <- jtb_search_keyword(site_reports, "Nausea", columns = mask)

identical(by_name, by_position)
#> [1] TRUE
identical(by_name, by_mask)
#> [1] TRUE
```

Positions are 1-based and refer to the columns of the table as read, so
`columns = c(5, 6)` is the fifth and sixth column. Leaving `columns` out
searches everything — convenient, but it means an identifier column can
match by accident:

``` r

# "R002" is a report id, not a comment; searching every column finds it.
jtb_search_keyword(site_reports, "R002")[, c("report_id", "term")]
```

|     | report_id | term   |
|:----|:----------|:-------|
| 2   | R002      | Nausea |

## Which one should you use?

Reach for
[`jtb_search_keyword()`](https://yh202109.github.io/jtb2026/reference/jtb_search_keyword.md)
when you know the exact string — a subject id, a coded term, a site name
— and you need *every* row that contains it. It is exhaustive and its
answer does not depend on any tuning.

Reach for
[`jtb_search_semantic()`](https://yh202109.github.io/jtb2026/reference/jtb_search_semantic.md)
when you are searching free text for an idea and you do not know how the
writer phrased it. It returns a ranked shortlist, so treat it as triage:
read the top of the list, not the whole thing.

A practical pattern is to use both. Rank first to find the vocabulary
people actually used, then keyword-search that vocabulary to get the
complete set:

``` r

shortlist <- jtb_search_semantic(site_reports, "stomach upset",
                                 columns = "comment", top_n = 5)
shortlist$comment
#> [1] "Stomach felt unsettled after each dose and the subject vomited once on Day 9."
#> [2] "Reported feeling sick to the stomach for an hour after dosing."               
#> [3] "Nauseous most mornings this cycle, improving by midday."                      
#> [4] "Subject felt queasy through the afternoon and skipped the evening meal."

# Having read those, the words worth an exhaustive search are clear.
complete <- jtb_search_keyword(site_reports,
                               c("queasy", "nauseous", "stomach", "vomited"),
                               columns = "comment")
complete[, c("report_id", "comment")]
```

|  | report_id | comment |
|:---|:---|:---|
| 2 | R002 | Subject felt queasy through the afternoon and skipped the evening meal. |
| 9 | R009 | Stomach felt unsettled after each dose and the subject vomited once on Day 9. |
| 17 | R017 | Nauseous most mornings this cycle, improving by midday. |
| 24 | R024 | Reported feeling sick to the stomach for an hour after dosing. |
